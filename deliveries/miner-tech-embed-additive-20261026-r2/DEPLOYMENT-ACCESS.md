# 部署方最小现场信息与权限

本文件只整理交接输入，不创建账号、不配置服务器、不新增发布平台。

部署方需提供：

- 实际系统和现有Web服务/版本、访问方式；确认OpenResty直服或Caddy链路，不从Server头推定完整架构。
- 实际releaseRoot、现有配置/spec位置、当前active及旧Tech/Field URL；说明现场额外自定义规则。任意Web配置不能直接更名为生成器JSON spec。
- 新版本目录可写位置、新URL如何映射、该路径CSP/XFO配置位置；原配置验证、平滑加载和回退命令及负责人。
- 现有SSH或CI发布通道、必要网络入口限制、可用部署时间；不需要在聊天中提供密码、私钥或完整凭据配置。

如使用可撤销SSH公钥账号：由部署方创建独立受限部署账号并登记提供的公钥（私钥留在执行方安全环境），限定来源与有效期。写权限只覆盖新release目录及必要暂存目录；旧release只读。若需配置加载，由部署方执行，或仅授予明确配置文件的验证/平滑加载受限命令；不默认root、不授予任意sudo shell或旧站点删除权限。完成后撤销公钥/账号或相关临时授权，保留执行日志。

如已有CI：复用当前流水线，授权读取本交付路径和下载指定SHA的ZIP、写入新版本目录、执行已有受控配置验证/加载及HTTP核验；凭据保存在既有CI secret中。由部署方审批共享配置变更，旧active保持，不授予修改其他项目/域名/全局头权限。不为此新建发布平台。

最小回传：实际新URL、核验脚本退出码和完整JSON、最终加载配置版本、旧入口发布前后状态/SHA，以及真实iframe准备→进入→操作→返回→再次进入结果。设备未测不签手机PASS。
