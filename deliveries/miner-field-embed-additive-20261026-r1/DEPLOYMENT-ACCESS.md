# 两站专用测试路径的自主发布通路

请部署方提供现有SSH或CI通路，使执行方可在约定权限内自主反复上传新版本、prepare/verify、核验响应头与资源、对指定路径配置做语法校验和受限reload，并撤回新路径映射或恢复该路径上次已验配置。仅覆盖Field与Tech各自专用测试版本目录；不新建发布平台，不修改原站默认入口。

需确认：

- 两站实际域名、Web服务与版本、release父目录、暂存目录、准确的新路径映射及CSP/XFO配置位置；不要猜现场active。
- 两站专用路径的配置文件边界、验证/reload/rollback受限命令、日志位置与回退步骤；共享server/CDN/父H5策略变更仍须单独确认。
- 可反复使用且可撤销的部署账号或现有CI权限、来源限制、有效期与负责人。原站、旧release、默认alias/active只读；不授予root、任意sudo shell、旧站删除或其他域名修改权限。
- 以指定commit和SHA读取交付、写新版本目录，执行包内核验；共享配置由部署方拆出精确路径权限，无法隔离时由其负责那一步，不扩成全站写权限。

SSH使用独立受限公钥账号，私钥留在执行方安全环境，不在聊天提供密码/私钥。CI复用既有secret，不把凭据提交仓库。权限应允许约定期内反复发布和回退，结束后可撤销并保留日志。

每次回传新URL、版本/SHA、verify退出码与JSON、实际配置版本，以及旧URL状态/location/SHA/content-type/cache-control/CSP/XFO前后对比。浏览器准备→进入→操作→返回→再次进入与设备验收分别记录，未测手机不签PASS。GitHub交付不代表服务器已部署。
